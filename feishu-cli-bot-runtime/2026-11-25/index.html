用 CLI 的 Bot 身份替换 IM Feishu 连接，并把 CLI 能力接给主 Agent

本文评审一个完整替换方案：以 lark-cli --as bot 作为飞书消息入口、消息出口和主 Agent 的飞书工具执行层，替代当前基于官方 SDK WSClient 的 IM 连接；同时把 CLI 在 Bot 应用身份下可用的完整能力接给主 Agent。

评审对象不是再接一个知识库，而是替换现有 IM 通道，并把 Bot 身份下的整套飞书能力纳入主 Agent。本文按章节覆盖现有链路、目标架构、数据流、能力矩阵、身份与权限、运行时状态、迁移回滚、性能安全、影响面和验收门槛。页面末尾支持按章节添加云端评审备注。

身份Bot 应用身份，tenant_access_token
凭据沿用 Cloud 加密 credentialRef 下的 App ID/Secret
能力IM、Wiki、文档、云盘、通讯录、审批、任务等受权能力
状态本机命令级已验证；真实企业与生产链路待验证

一、评审结论与方案边界

技术上可以形成完整替代方案；核心工程不是“把 SDK 换成 CLI 命令”，而是把 CLI 治理成服务侧的消息消费者、API 执行器与主 Agent 工具面，同时迁移现有连接状态和可靠性语义。

替换

当前 WSClient 长连接、IM API 调用、卡片与附件发送、飞书 SDK 凭据读取方式。

保留

Cloud 连接与群绑定、线程映射、审批状态、durable delivery、Agent 会话、same-card 状态机和监控语义。

新增

CLI 进程生命周期、事件总线、中心化凭据、命令白名单、审计、输出契约和主 Agent 的全域飞书工具。

不写入本评审的内容用户个人 OAuth、以用户名义访问私人日历/邮箱、尚未确认的产品决策表。CLI 的 --as user 不作为本次方案的一部分。
真实验证边界本机已验证命令参数、事件 schema 与 Bot 身份声明；没有执行企业授权、真实群消息/卡片事件、知识库正文召回或线上等价回归。本文是待评审技术方案，不是已上线结论。

二、现有 IM Feishu 连接

当前链路从 Settings 的 app registration 开始，Cloud 保存应用凭据与连接状态；官方 SDK 建立长连接，Cloud 通过 durable delivery 把事件送到执行侧，renderer 负责卡片与消息出口。

层现状关键状态 / 契约替换时的约束
应用注册Settings 扫码；后端轮询 app registration，返回 App ID/Secret、Bot open id、扫码用户、tenant 与 6 项应用身份 IM scope。credentialRef 加密保存；用户与 App 绑定；历史 UAT 记录过跨应用 open_id 错误。新应用必须保留同一套连接归属和用户标识，不能只替换凭据。
事件入口Cloud/local runtime 用 App ID/Secret 构建 lark.WSClient，处理消息与卡片事件。连接状态、重连计数、事件去重、群绑定、线程与审批意图。CLI 事件消费者要输出等价事件字段，并保持幂等键和连接状态。
执行与投递Cloud durable delivery 把事件送 Desktop/local backend；Agent 执行后回写消息、卡片、审批与附件。same-card working/final/error、AskUserQuestion、审批幂等、outbox、delivery lease。业务语义继续由现有 Cloud/Desktop 链路拥有，避免整系统重写。
消息出口renderer 通过飞书 SDK 发文本/富文本/卡片、更新流式卡片、处理附件。credentialRef、消息 ID、threadLink、phase、卡片 token 与失败状态。CLI 适配层必须保持现有 renderer 的输入输出契约。

三、目标架构：CLI 作为 Bot Runtime

飞书企业应用消息、卡片、知识库、文档等事件与资源
→
CLI Bot Runtimeevent consume --as bot / IM + API --as bot
→
主 Agent统一工具面，受授权范围与审计约束

控制面：Cloud 凭据与连接

  • 沿用 Cloud 的连接、群绑定、用户归属与 credentialRef 加密存储。
  • 每个活跃连接对应一个隔离 CLI profile；App Secret 从服务端凭据源注入，不落进程参数和日志。
  • 应用配置 readiness 核对：tenant scope、事件订阅、机器人能力、长连接模式与已发布版本。
  • 连接状态、启动/停止、租约、升级和回滚仍由 Cloud 编排。

数据面：事件消费者与执行器

  • 消息事件和卡片事件分别由长期 CLI 消费者订阅，NDJSON 输出到 Cloud 事件入口。
  • 调用侧统一封装 --as bot：IM、卡片、附件、Wiki、Docx、Drive、Contact、Task 等命令。
  • 所有外部输出转成现有内部事件/工具结果类型；CLI 版本差异在适配层收敛。
  • 主 Agent 只看到按 connection 与资源白名单过滤后的能力，不直接构造任意 CLI 命令。
为什么不是简单换认证CLI 是子进程与命令协议，不是进程内 SDK。目标方案必须新增消费者管理器、进程健康、输出解析、凭据供给和命令治理，才能承担原来的生产消息链路。

四、事件与消息数据流

路径目标架构数据契约失败与补偿
入站消息event consume im.message.receive_v1 --as bot → 解析 NDJSON → 现有 IM 事件入口 → Cloud delivery → 主 Agent。message_id 为消息幂等键；event_id 仅作投递标识；保留 chat_id、chat_type、sender_id、thread/root/reply、mentions、content、message_type。进程退出自动拉起；断线恢复后按 message_id 去重；消费者不可用触发告警，不静默丢事件。
卡片动作event consume card.action.trigger --as bot → 动作事件 → 审批意图与幂等检查 → Agent/审批链路。action_tag/value、operator_id、message_id、chat_id、token、form_value；token 有有效期与更新次数限制。重复点击按既有审批 intent 去重；卡片 token 失效时给用户可理解提示。
出站回复现有 renderer 产生内部消息动作 → CLI adapter → IM 发送/卡片更新/附件 → Cloud 记录投递结果。保持 working/final/error same-card、threadLink、credentialRef、审批卡片目标与附件元数据。失败进 outbox/重试；限频退避；不允许跨 connection 使用凭据。
Agent 飞书工具主 Agent 发起工具调用 → 能力网关校验 connection/scope/资源 → CLI 命令 → 结构化结果 → 证据/引用。工具名、参数、结果大小、引用链接、资源 ID、耗时、错误分类；不回传 token 或 Secret。缺 scope、资源 ACL、限频、无结果分别处理；写操作需确认策略与审计。
状态所有权CLI 只负责飞书侧收发与 API 执行。群绑定、线程映射、审批状态、Agent 会话、outbox、delivery lease 和 same-card 状态仍由现有 Cloud/DB 拥有；否则会变成整个系统重写。

五、完整 CLI 能力接入主 Agent

CLI v1.0.100 的业务域包括 IM、Wiki、Doc、Drive、Contact、Approval、Task、Calendar、Mail、Base、Sheets、Slides、Minutes、Note、VC、Whiteboard、OKR 等。这里按“Bot 应用身份可用且产品需要的范围”评审，不等于把全部命令无差别开放给 Agent。

能力层接入内容主 Agent 工具面评审重点
消息与协作消息收发、群/成员查询、卡片创建与更新、附件上传下载、审批实例/任务、通讯录。im.send / reply / read、card.update、contact.lookup、approval.query。替换前后的消息等价性、审批幂等、附件大小与临时文件清理。
知识与文档知识空间、节点解析、Wiki/Doc 搜索、docx 纯文本/blocks、Markdown 文件、Drive 文件与权限元数据。wiki.search / read、doc.read、drive.list / read。空间 ACL、引用字段、分页、5 QPS 限频、正文按需读取与增量缓存。
结构化数据Base、Sheets、白板、幻灯片、会议纪要与笔记内容。按业务域逐步开放只读工具；写工具单独评审。内容结构与上下文体积，避免把整库或大表无边界塞入 Agent。
组织与效率Calendar、Task、OKR、VC、Minutes、Attendance 等 Bot 被授权的企业资源。任务查询、日程查询、会议资料读取等能力按域灰度。明确区分企业资源和个人私人资源；Bot 身份不能代表用户操作个人数据。
应用与平台应用版本、scope、事件订阅、应用配置与 api/schema 逃生口。仅运维/诊断工具，不暴露给普通 Agent 会话。命令白名单、high-risk-write 阻断、原始 API 调用审计。
能力开放原则应用的全部 tenant scope 是上限；主 Agent 的实际能力由 connection、工具白名单、资源 ACL、写操作确认和审计共同决定。先开放只读与消息基础能力，再逐域评审写操作。

六、身份、凭据与权限

身份链

  • --as bot 使用 App ID/Secret 换 tenant token，调用身份是 Bot 应用。
  • 不需要 auth login、用户 UAT 或用户 refresh token；截图中的 171 项个人授权不进入方案。
  • 应用身份权限、事件订阅、机器人能力、长连接模式和已发布版本是独立配置面，需读取应用版本元数据核对。
  • 新应用与旧应用切换会导致 open_id 与 Bot open id 变化，用户绑定和群绑定必须做映射。

凭据链

  • Cloud credentialRef 保持为权威凭据源；CLI profile 只作为运行时投影。
  • 企业内嵌通过 Go extension 的 Credential Provider 从 Vault/DB 注入 App ID/Secret/TAT；Secret 不进入命令行、日志或 API DTO。
  • profile 目录按 connection 隔离，连接撤销时删除本地投影并停止事件消费者。
  • Transport/Restrict/Observer/Wrap/On 分别负责网络、命令白名单、审计、错误包装与生命周期事件。
资源 ACL 是第二道门即使 tenant scope 完整，Bot 也必须加入目标群、知识空间或文档协作范围。无权限、空间为空和文档不存在要返回不同错误，不能混成“没有内容”。

七、运行时、状态与可靠性

主题方案要求评审风险验证方式
进程生命周期每个活跃 connection 的消息/卡片消费者由管理器登记；启动、ready、退出、重启、升级、删除全部有状态机。CLI 子进程崩溃、stdout 阻塞、bus daemon 孤立、热升级重复消费者。杀进程、重启、重复启动、配置变更、连接删除的真实故障注入。
事件完整性NDJSON 逐行解析，保留 event/message id；error 与 drop 诊断进入日志；--quiet 不用于生产。stdout 缓冲、管道破裂、事件丢失、同一事件双消费。消息和卡片各回放重复事件，核对去重与审批幂等。
多实例与租约connection 级 lease 保证同一时刻只有一个有效消费者；Pod 重启时先释放旧租约再接管。多 Pod 同时收事件；旧消费者未退出仍投递。两实例并发、抢占、过期与网络分区测试。
状态兼容同/异步卡片、working/final/error、AskUserQuestion、附件、审批意图、outbox、durable WSS 保持现有 DB 语义。CLI 输出字段与 SDK 事件字段差异导致 threadLink 或卡片状态丢失。逐项对比现有 UAT：群聊、私聊、卡片、附件、审批、断线重连。
可观测性消费者健康、事件延迟、API 延迟/错误码、限频、重连次数、命令审计与配置 readiness 接入现有监控告警。只监控进程存活，看不到静默丢消息和权限错误。告警演练：权限缺失、事件订阅丢失、CLI 退出、TAT 失败。

八、迁移路径与回滚

  1. 真实应用 UAT

    核对已发布版本的 token_types 与 event_infos；在测试群、测试知识空间验证消息、卡片、附件、知识库正文与权限错误。

  2. 控制面接入

    Cloud 凭据源提供隔离 profile；建立消费者管理器、lease、健康状态和命令白名单；旧链路继续服务线上。

  3. 入站影子消费

    CLI 消费者只接收并比对事件，不驱动 Agent；检查字段、延迟、重复和缺失，形成等价性报告。

  4. 出站单群灰度

    选择一个群切到 CLI 文本/卡片/附件发送，保留旧 renderer 作为回滚路径；验证 same-card 与审批幂等。

  5. 主 Agent 工具灰度

    先开放 Wiki/Doc 只读和引用；按域开放 Drive、Contact、Task 等能力；写操作经确认与审计。

  6. 逐连接切换

    按 connection 迁移，记录新旧应用标识与 open_id 映射；监控每个连接的状态与错误率。

  7. 退出旧通道

    所有验收门槛通过后停用旧 WSClient 与 SDK 依赖；保留一个发布周期的快速回滚开关。

推荐替换边界用 CLI 替换飞书通道和工具执行层，保留现有 Cloud/Desktop 业务状态与 Agent 调度。这样能获得完整 CLI 能力，同时避免把 P0 扩张成整个系统重写。

九、性能、数据流与安全审计

性能与数据流

  • 列表只取展示字段，正文按需读取；分页必须处理空页但 has_more=true；docx raw_content 遵守 5 QPS 与退避。
  • 知识库搜索返回候选标题、space/node/obj token、url、更新时间；按内容 hash 做增量缓存。
  • Agent 工具返回片段和引用，不把整库正文或大表无边界塞入上下文。
  • 关注 CLI 冷启动、子进程并发、长连接消费者常驻与 API 子进程调用的成本差异。
  • 按仓库既有验收习惯，审查 SQL 查询字段、重复查询/N+1、完整 BLOB 误读、缓存和下载路径。

安全与审计

  • 所有命令强制 Bot 身份；禁止主 Agent 自由拼接命令或切换 --as user。
  • 写操作、high-risk-write 和 api 原始调用进入显式策略；默认只读白名单。
  • 按 connection/用户/群/空间校验资源，不让一个会话使用另一个连接的凭据或资源 ID。
  • 记录工具名、身份、参数摘要、结果状态、错误码和耗时；token、Secret、消息正文不进入审计日志。
  • 配置撤销、连接删除后立即停止消费者并清理本地 profile；撤权文档不再返回旧缓存。
